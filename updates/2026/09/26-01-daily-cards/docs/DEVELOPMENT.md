# 기능 추가를 결정한 과정

## 출발점

기존 앱은 20개 질문을 풀고 연애 성격 유형과 이미지를 받는 가벼운 구조였습니다. 운영자가 신규 기기 획득의 누적 증가를 관찰하고 재방문할 콘텐츠를 검토했습니다. 누적 획득 증가만으로 재방문이 늘었다고 판단하지는 않았습니다.

## 선택한 두 기능

매일 달라지는 연애 상황 한 문항으로 들어올 이유를 만들고, 답변을 카드로 모아 다시 볼 이유를 만드는 방향을 택했습니다. 회원가입·서버·AI 상담을 새로 만들지 않고 로컬 콘텐츠와 저장소로 구현 범위를 정했습니다.

## 구현 설계

- 기존 성격 테스트 점수와 일일 질문 결과를 분리합니다.
- 하루 한 기록을 날짜 키로 관리합니다. 같은 날 답변을 바꾸면 교체합니다.
- 질문 30개를 주제가 섞이도록 고정 순서로 배정합니다.
- 질문·네 선택지·결과 문구를 스냅샷으로 저장합니다.
- 목록과 결과 화면에서 같은 기록을 읽고 즐겨찾기를 바꿉니다.
- 공유 도면을 별도로 만들어 광고·조작 버튼 없이 PNG로 보냅니다.

## 현재 확인한 구현

신규 데이터 모델, 질문 데이터, 스케줄러, 저장소, 어댑터, 공유 렌더러가 추가됐습니다. MainActivity와 activity_main.xml 안에 기존 테스트와 신규 화면이 연결됩니다. 새 화면을 별도 Activity로 나눈 구조는 아닙니다.

## 검증하며 배운 점

구현 보고의 표현과 실제 코드는 구분해야 했습니다. 복원한 선택값을 화면 초기화가 다시 지우는 흐름, 저장 오류를 빈 목록으로 반환하는 흐름, 날짜 검사에 불필요한 조건이 추가된 부분을 확인했습니다. 오류를 잡는 try/catch가 있다고 데이터 보존까지 보장하는 것은 아닙니다.

테스트 통과 3개 중 신규 기능 테스트는 2개, 나머지는 기본 덧셈 예제였습니다. 날짜 테스트는 실제 스케줄러가 아니라 복사된 수식을 검사하므로 보완해야 합니다.

## 아직 측정하지 않은 성과

이번 기능이 실제 재방문율·공유율을 높였는지는 측정 결과가 없습니다. 기능 구현 사실과 제품 성과를 구분합니다. 다음 단계에서는 설치 다음 날·7일 뒤 재방문, 일일 질문 완료, 카드 공유 같은 지표를 검토할 수 있습니다.
