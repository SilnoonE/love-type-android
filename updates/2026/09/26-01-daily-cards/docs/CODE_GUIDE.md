## 연애 성격 테스트 오늘의 질문과 카드 모음집

공개용 개발 요약 · 2026.09.26


### 일회성 결과에서 다시 방문할 콘텐츠로


기존 앱은 20개 문항을 풀고 연애 성격 결과와 이미지를 확인하는 구조였습니다. 가벼운 사용감을 유지하면서 재방문할 계기를 만들기 위해 오늘의 연애 상황 질문과 답변 카드 모음집을 추가했습니다.


| 기능 | 사용 경험 |
| --- | --- |
| 오늘의 질문 | 하루에 한 상황을 읽고 네 선택지 중 하나를 선택 |
| 결과 카드 | 선택에 연결된 짧은 해석과 대화 문구 확인 |
| 모음집 | 지난 답변을 날짜별로 모으고 즐겨찾기로 다시 보기 |


### 이 문서의 범위


기능을 선택한 이유, 화면 흐름, 주요 코드 구조와 검증 범위를 8쪽으로 요약합니다. 상세한 개인 학습 지침, 파일별 전체 해설, 장문의 코드 주석은 포함하지 않습니다.


> 전체 앱 소스는 저장소의 source 폴더에서 별도로 열람할 수 있습니다. 이 PDF는 공개 소개와 개발 과정 설명을 위한 요약본입니다.


## 01. 기능과 화면 흐름

매일 한 번의 짧은 선택


### 홈에서 세 가지 길을 제시


홈 상단에는 오늘의 질문을 두고, 아래에 기존 성격 테스트와 최근 답변 카드 세 개를 배치했습니다. 신규 기능과 기존 테스트를 한 화면에서 찾을 수 있도록 구성했습니다.


| 단계 | 처리 |
| --- | --- |
| 홈 | 답변 전에는 답하기, 답변 후에는 카드 보기 표시 |
| 질문 | 선택 상태를 표시하고 제출 전에는 영구 저장하지 않음 |
| 결과 | 제목·해석·대화 문구와 원래 질문·선택 답을 표시 |
| 모음집 | 최신순 기록, 전체·즐겨찾기 필터, 상세 진입 |
| 공유 | 공유용 카드만 PNG로 전달 |


### 적은 기능으로 시작


새 계정·서버·AI 상담 없이 앱에 포함된 콘텐츠와 기기 내 저장으로 구현 범위를 정했습니다. 오늘 질문의 결과는 미리 작성한 선택지별 문구이며, AI가 실시간으로 진단하는 기능은 아닙니다.


> 기존 성격 테스트는 여러 답변의 점수를 합산합니다. 일일 질문은 고른 선택지의 해석을 표시합니다. 두 결과 체계는 분리돼 있습니다.


## 02. 코드 구조

데이터와 화면, 저장의 책임 분리


| 구성 요소 | 담당 역할 |
| --- | --- |
| MainActivity | 버튼 연결, 화면 상태, 화면에 값 표시 |
| DailyCardModels | 질문·선택지·기록의 데이터 형식 |
| DailyQuestionData | 일일 질문과 선택지별 결과 문구 |
| DailyQuestionScheduler | 날짜에 맞는 질문 결정 |
| DailyCardRepository | 기록 읽기, 추가·수정, 즐겨찾기 저장 |
| DailyCardAdapter | 목록 항목과 기록 연결 |
| DailyCardShareRenderer | 공유용 레이아웃을 이미지로 변환 |


### 현재 구현 방식


하나의 MainActivity와 XML 레이아웃 안에서 화면을 숨기고 필요한 화면을 보여줍니다. 반복되는 선택지와 카드 목록 항목은 별도 XML로 만들어 재사용합니다.


### 상태를 구분하는 이유


아직 제출하지 않은 선택, 현재 화면, 필터는 임시 화면 상태입니다. 완료한 답변과 즐겨찾기는 앱을 다시 켜도 남겨야 하는 기록입니다. 화면 복원과 영구 저장을 별개로 다뤄야 합니다.


## 03. 날짜별 질문 선정

같은 날에는 같은 질문


첫 사용일을 기준 날짜로 저장하고 오늘까지 지난 일수를 계산합니다. 고정된 30개 질문 순서의 위치를 구하므로 앱을 같은 날 다시 켜도 질문이 바뀌지 않습니다.


```kotlin
val days = ChronoUnit.DAYS.between(anchorDate, targetDate)
val index = Math.floorMod(days, 30L).toInt()
val questionId = fixedOrder[index]
```


| 경과 일수 | 목록 위치 | 의미 |
| --- | --- | --- |
| 0 | 0 | 첫 번째 질문 |
| 1 | 1 | 다음 질문 |
| 29 | 29 | 마지막 질문 |
| 30 | 0 | 첫 질문으로 순환 |


목록 번호는 0부터 시작합니다. floorMod는 음수 일수도 유효한 목록 위치로 바꿉니다. 날짜가 기준이므로 방문하지 않은 날도 순서는 진행하고, 30일 뒤에는 질문이 반복됩니다.


> 이미 그날의 기록이 있으면 계산한 현재 콘텐츠보다 저장된 질문 스냅샷을 우선합니다. 자정에 화면을 갱신하는 것과 제출 직전 날짜를 검증하는 것은 별도 처리입니다.


## 04. 기록과 스냅샷

같은 날짜는 수정, 다른 날짜는 추가


| 저장 항목 | 목적 |
| --- | --- |
| 날짜 키 | 하루 한 기록을 구분 |
| 질문 ID·선택 ID | 어떤 질문의 어느 답인지 식별 |
| 질문 스냅샷 | 당시 질문과 결과 문구를 함께 보존 |
| 즐겨찾기 | 나중에 다시 볼 기록 표시 |
| 생성·수정 시각 | 처음 작성한 순간과 답변 변경 시각 구분 |


### upsert의 의미


같은 날짜의 기록이 있으면 답변을 교체하고 없으면 새 기록을 만듭니다. 같은 날 여러 번 답을 바꿔도 카드 수는 늘지 않습니다. 기존 즐겨찾기와 최초 생성 시각은 답변 수정 시 유지하는 구조입니다.


### 현재 저장 방식


객체를 JSON 문자열로 바꿔 전용 SharedPreferences에 저장합니다. 쓰기는 단일 executor에서 순서대로 수행하고 commit 결과를 화면에 전달합니다. 읽기와 JSON 해석은 호출한 스레드에서 수행합니다.


> 읽기 실패와 실제 빈 기록은 구분해야 합니다. 예외를 잡는 것만으로 데이터 보존이 보장되지 않으므로 오류 상태와 원본 보호가 필요합니다.


## 05. 모음집과 이미지 공유

같은 기록을 여러 화면에서 활용


### 모음집


저장소의 최신순 기록을 목록에 전달합니다. 즐겨찾기 필터는 원본 기록을 삭제하지 않고 화면에 보여줄 목록만 골라냅니다. RecyclerView 어댑터는 제목·날짜·그림·즐겨찾기 상태를 각 항목에 채웁니다.


### 공유 과정


| 순서 | 처리 |
| --- | --- |
| 1 | 공유 전용 XML 레이아웃 생성 |
| 2 | 기록의 문구와 주제별 그림을 채움 |
| 3 | 가로 1080px, 내용에 맞는 높이로 측정 |
| 4 | Canvas로 Bitmap에 그리고 PNG로 저장 |
| 5 | FileProvider의 content URI로 공유 앱에 전달 |


앱 전체 화면을 캡처하지 않으므로 광고나 조작 버튼이 공유 이미지에 들어가지 않습니다. 이미지는 캐시에 저장하며 공유용 읽기 권한을 전달합니다.


> 연속 공유에서는 파일명 충돌, 긴 문구에서는 이미지 높이와 메모리, 화면 종료 시에는 비동기 콜백 처리를 확인해야 합니다.


## 06. 검증 범위와 보완점

구현 보고와 직접 확인한 사실을 구분


### 확인한 범위


로컬 소스를 읽어 질문 30개·선택지 결과 120개, 파일 역할과 데이터 연결을 확인했습니다. 기존 테스트 결과 파일에는 신규 기능 테스트 2개와 기본 덧셈 예제 1개가 통과한 기록이 있습니다.


이 공개 문서 정리 과정에서 Android 빌드·단위 테스트·실기기 동작을 새로 실행하지 않았습니다. 사용자에게 전달받은 빌드 성공 보고와 직접 재실행한 검증을 구분합니다.


| 영역 | 보완하며 확인할 점 |
| --- | --- |
| 상태 복원 | 복원한 선택을 화면 초기화가 덮지 않는지 |
| 날짜 | 자정 경과와 제출 직전 날짜 검사 |
| 저장 | 손상 JSON을 빈 목록으로 취급하지 않는지 |
| 입력·생명주기 | 저장 중 연타와 종료된 화면의 콜백 |
| 공유 | 연속 요청의 파일 덮어쓰기 |
| 테스트 | 복사한 수식이 아닌 실제 사용 함수 검증 |


> 표는 정적 코드 검토로 확인한 보완 방향입니다. 실제 기기에서 모두 재현하거나 수정 완료했다는 뜻은 아닙니다.


## 07. 개발 기록을 남기는 방식

공개 요약과 개인 학습 자료를 구분


### 업데이트는 누적 보관


날짜와 순번별 폴더에 당시 소스·개발 설명·검증 범위를 모으고 커밋과 태그로 보관 시점을 구분합니다. 다음 작업은 새 폴더에 추가해 이전 개발 과정을 계속 볼 수 있도록 합니다.


### 공개 자료의 기준


공개 PDF는 10쪽 이내로 제한하며 이번 문서는 8쪽입니다. 상세 개인 학습 해설을 공개 문서에 그대로 복제하지 않습니다. 운영 광고 ID·서명 키·인증정보·개인 데이터는 업로드 대상에서 제외합니다.


### 이번에 배운 점


작은 기능도 날짜, 저장 실패, 화면 재생성, 연속 입력 같은 경계 상황을 함께 다뤄야 합니다. 빌드 성공과 실제 사용 흐름의 완성도는 같은 말이 아니며, 코드·검증 결과·제품 성과를 구분해 기록해야 합니다.
